# Журнал решений

Одна строка — одно решение: что выбрал и почему.

## Технологии
- GSAP 3.12.5 + ScrollTrigger лежат локально в `/vendor`, а не на CDN: cdnjs из рабочей среды недоступен (403 от прокси), а локальная копия ещё и не зависит от чужого сервера.
- Шрифты из Google Fonts скачаны в `/fonts` (woff2, кириллица + латиница, вариативные): быстрее, работает офлайн и при открытии `index.html` файлом.
- Шрифты: Cormorant Garamond (антиква для заголовков), IBM Plex Sans (текст), IBM Plex Mono (спецификации, цены, размеры) — все с кириллицей, без Inter/Roboto/Space Grotesk.
- Глиф ₽ лежит в latin-ext подмножестве — подключил его отдельным файлом с `unicode-range: U+20BD`, браузер скачивает его только ради знака рубля.
- Lenis не подключал: на телефонах плавный скролл часто конфликтует с pin-секцией и адресной строкой, а нативный скролл + `scrub` в ScrollTrigger даёт достаточно мягкости.
- WebGL не использовал: вся графика — SVG, это легче, доступнее и не требует фолбэка.
- SVG часов генерирует скрипт `tools/gen-watch.mjs` и вписывает между маркерами `<!-- GEN:… -->` в `index.html`. Сайт сборки не требует — скрипт нужен только чтобы менять геометрию.
- Повторяющиеся элементы (60 меток минутной шкалы, 120 рисок безеля, пылинки, царапины) склеены в один `path`: DOM уменьшился с ~1660 до ~1200 узлов, Lighthouse перестал ругаться на main thread.

## Разборка часов
- «3D» без WebGL: каждая деталь — диск в группе `.tilt`, наклон делается `scale(k,1)` (ортографическая проекция поворота вокруг вертикальной оси). Стрелки вращаются внутри наклонённой группы — проекция получается честной.
- Прогресс сцены (0…1) считает ScrollTrigger со `scrub`, а трансформации SVG выставляю сам через атрибуты: так нет сюрпризов с `transformOrigin` у вложенных SVG-групп.
- Раскладка считается от реального размера экрана: `viewBox` = размер сцены в «единицах», поэтому подписи не мельчают на больших мониторах и не раздуваются на маленьких.
- Широкий экран — горизонтальный разлёт, подписи сверху и снизу со «жадной» раскладкой без пересечений. Узкий/портретный — вертикальный разлёт, подписи колонкой справа.
- Выноски — по ГОСТ-логике: точка на детали, наклонная линия-выноска, полка с номером позиции. Рисуются через `stroke-dashoffset`.
- Ремешок в разлёте становится штрихпунктирным «условным изображением» (так на чертежах показывают смежные детали), на телефоне скрыт — упрощённый разлёт.
- Заводная головка вынесена вверх над корпусом, а не вправо по оси: справа место занято задней крышкой, а на чертеже детали разносят так, чтобы они читались.
- Подписи выносок берутся из списка спецификации (`#parts-list`, атрибут `data-short`) — один источник текста.
- Баланс качается медленнее реальных 4 Гц (период 1,8 с): в ТЗ «тихо качается», а настоящая частота на экране выглядит как дрожание.
- Секундная стрелка «тикает» 8 раз в секунду, как у механики на 28 800 пк/ч; при reduced-motion — раз в секунду без плавности.
- До запуска JS часы стоят примерно там же, где их поставит раскладка (CSS-позиция сцены), и видны сразу: раньше SVG прятался до инициализации и становился LCP на 4,5 с.
- reduced-motion и отсутствие GSAP → сцена не закрепляется, сразу показывается статичная схема «в разборе». Без JS — собранные часы и полная спецификация текстом.
- Лупа: `<use href="#watch">` внутри круглого `clipPath`, ×2,5; только для мыши (`hover: hover` и `pointer: fine`).

## Графика и цвет
- Палитра: графит `#121110`, латунь `#c9a25b`, слоновая кость `#ece3cf`, линии цвета старой бумаги `#cfc2a6` с прозрачностью. Вторичный текст `#b9b0a0`/`#a39a88` — контраст ≥ 6:1.
- График суточного хода: цвета «до» `#5d82c8` (воронёная сталь) и «после» `#b88a2e` (латунь) прогнаны через валидатор палитр — проходят по различимости для дальтоников и контрасту на тёмном фоне. Есть легенда, подписи крайних значений, скрытая таблица с данными и всплывающие подсказки у столбиков.
- Иллюстрации «до/после» — те же SVG-символы часов и механизма плюс слои «грязи», царапин и трещин, сгенерированные детерминированным ГПСЧ.

## Проверка
- Python `http.server` не сжимает файлы, и Lighthouse на нём даёт 64 за производительность из-за отсутствия gzip. GitHub Pages отдаёт gzip, поэтому для честного замера написал `tools/serve.mjs` (gzip + кэш) — на нём mobile 93+.
- Полные скриншоты страницы делаются с отключённым pin (иначе на месте закреплённой сцены пустой «распорщик»); состояния разборки сняты отдельными кадрами.
- В скриптах проверки прокрутка `behavior: 'instant'`: у страницы `scroll-behavior: smooth`, и обычный `scrollTo` не успевал доехать.
- Скрытая таблица данных графика давала горизонтальный скролл на телефоне (таблицы игнорируют `width: 1px`) — обернул её в `div.visually-hidden`.
- OG-обложка — JPEG 1200×630 (~95 КБ вместо 440 КБ PNG), снята Playwright со страницы с дополнительным оформлением.

## Фото-версия (ноябрь 2026)
- Фото из корня перенесены `git mv` в `img/raw/` (исходники, не грузятся сайтом). Сайт использует только `img/photo/` — AVIF + WebP в 640/1280/2048 px, их делает `tools/process-photos.mjs` (sharp).
- У всех фото 02–09 фон уже прозрачный (проверил альфа-канал) — вырезать чёрный фон и `mix-blend-mode` не понадобилось.
- Детали сгенерированы ИИ с разным масштабом и смещением. Выровнял по альфа-каналу: центр — середина самой широкой строки (у колец — середина внутреннего отверстия, у корпуса — отверстие без головки, у ротора — ось), масштаб — к реальному диаметру в мм (стекло 31,5, безель 38,4, циферблат 30, механизм 26, ротор 25, корпус 39, крышка 37) при 46 px/мм. Все слои лежат на одинаковом холсте 2048×1600 с центром в (950, 700) — в CSS их можно просто класть друг на друга.
- Стекло снято более плоским, чем остальные детали (отношение осей эллипса 0,45 против ~0,63) — растянул его по вертикали ×1,3, чтобы наклон совпал.
- Порядок разлёта — по нумерации файлов: стекло → безель → стрелки → циферблат → механизм → ротор → корпус → крышка (сверху-слева вниз-вправо). Физически корпус надевается раньше циферблата, но если положить его выше, он закрывает циферблат и механизм — читаемость важнее.
- Позиции на чертеже переименованы под фото: 8 позиций (01 стекло … 08 задняя крышка), заводная головка — часть корпуса (поз. 07), баланс заменён ротором автоподзавода (он есть на фото). SVG-фолбэк перекрашен под фото (сталь, графит, латунь) и тоже получил ротор вместо баланса — схема и фото описывают одни и те же часы.
- **Стрелки.** На фото 05 стрелки сняты в перспективе в одном положении (10:08) — повернуть их «по времени» нельзя без искажения. Поэтому слой «03 Стрелки» в разборе — живые SVG-стрелки в плоскости циферблата (поворот, затем сжатие по вертикали ×0,62 — как у эллипса циферблата), ось — в центре отверстия циферблата (952, 685 на холсте). Цвет и форма — как на фото 05. Само фото 05 не используется.
- **Hero.** На фото 01 стрелки «впечатаны», их не убрать без ретуши — hero статичен. Живое время на странице показывают логотип и стрелки в разборе.
- Переход hero → разбор: стопка слоёв встаёт точно на место корпуса фото 01 (ось стрелок фото = ось циферблата слоёв, ширина корпуса 1557 px на фото = 1794 px на холсте), фото и слои меняются наплывом, пока стопка едет в центр и начинает раскрываться.
- Фото hero не переносится скриптом в другой контейнер, а двигается только `transform`: перестановка узла создавала новое LCP (+1,5 с). По той же причине на телефоне фото стоит под текстом средствами CSS (в потоке флекс-колонки), а не скриптом.
- Верх ремешка на телефоне гасится маской (`mask-image`), чтобы не мешал тексту; градиентная подложка под текстом убрана — она затемняла слои разборки.
- Широкий экран: подписи верхних четырёх деталей — справа, нижних — слева (пустые углы диагонали); колонки не заходят на циферблат и механизм. Телефон/планшет: почти вертикальный разлёт, подписи колонкой справа, стопка с подписями по центру.
- Лупа в фото-режиме — клон фото-сцены в круглом окне ×2,5 (картинки в клоне просят `sizes=100vw`, поэтому под лупой подгружаются 2048-px версии).
- **Фолбэк.** reduced-motion → статичная SVG-схема в разборе (фото hero остаётся). Если не загрузилось фото hero или любой слой (`error`) → сцена переключается на SVG-разборку на лету. Без JS — фото hero + собранные SVG-часы + спецификация. Проверено скриптом: при заблокированном слое 06 сцена ушла в `mode-svg`, ошибок JS нет.
- Кейс 03 «треснувшее стекло» остался SVG-иллюстрацией (фото для него нет), часы в нём перекрашены под фото.
- **Производительность.** Слои — `loading="lazy" fetchpriority="low"`, hero — `fetchpriority="high"` + `preload` только AVIF. AVIF hero сжат сильнее (q 44, 48 КБ для 1280). Шрифты пересобраны через Google Fonts `text=`: один файл на начертание (кириллица + латиница + ₽ № ± × Ø ≈), 5 файлов / 163 КБ вместо 12 / 240 КБ. Инициализация сцены разбита на три задачи (setTimeout), чтобы не было длинной задачи на 220 мс. Итог Lighthouse mobile 91–92 (несколько прогонов), desktop 100.
- srcset у слоёв 640/1280/2048, хотя на телефоне слой занимает ~170 px: меньше 640 в задании не было, Lighthouse считает ~60 КБ «лишними» — приемлемо.
- Исходники `img/raw/` (47 МБ PNG) удалены из репозитория (`git rm`, без переписывания истории) и занесены в `.gitignore`: хранятся локально у автора, сайт их не загружает. В старых коммитах они остаются — история не переписывалась.
